Tema 1 de 4

Arquitectura Lakehouse

La misma agua, otra profundidad

La represa no es un cuerpo de agua distinto — es el mismo caudal, llevado a otra profundidad para poder aprovecharlo de otra forma. Delta Lake es el material de esa represa: un formato abierto que garantiza transacciones confiables (ACID) sobre el dato guardado, y que se pueda auditar en el tiempo.

1 · Bronze

El agua tal cual llega

El dato crudo, sin validar, en su formato original.

+ tocá para ver más
Es el mismo principio que ya vimos en Datasphere con la Ingesta — acá Databricks lo llama Bronze, pero es la misma idea: preservar el dato tal cual salió del origen, sin tocarlo.
→
2 · Silver

Decantada y filtrada

Limpieza, deduplicación, normalización.

+ tocá para ver más
Equivale a la Armonización: acá se corrigen errores e inconsistencias, antes de que el agua esté lista para usarse.
→
3 · Gold

Lista para la turbina

Datos de negocio, agregados y optimizados para consumo.

+ tocá para ver más
El Data Product de Databricks: organizado por proyecto, listo para reporting o para entrenar un modelo.
↕ Unity Catalog — corre por debajo de las tres capas, todo el tiempo: control de acceso a nivel de columna, linaje y auditoría, sin herramientas separadas.

Postura DanworPostura recomendada

Usar tablas gestionadas por Unity Catalog en las tres capas — de Bronze a Gold — en vez de mezclar con almacenamiento no gestionado: es la forma recomendada de mantener gobierno y linaje consistentes de punta a punta.

Tema 2 de 4

Unity Catalog

Un solo gobierno, para el agua y la turbina

Así como el comité de cuenca acordaba una sola norma entre dominios, Unity Catalog es el tablero de control único de la represa: gobierna no solo las tablas, sino también los modelos de IA que se construyen con esos datos.

Datos

Tablas, vistas, volúmenes

El mismo catálogo de siempre, con jerarquía catalog → schema → table.

+ tocá para ver más
Control de acceso a nivel de columna, linaje automático y audit logs — sin herramientas separadas.
+
IA

Modelos, features, funciones

Los activos de Machine Learning, gobernados con las mismas reglas.

+ tocá para ver más
Un modelo entrenado y una tabla de ventas viven bajo el mismo permiso, el mismo linaje, la misma auditoría.
Antes, gobernar el dato y el modelo de Machine Learning eran dos mundos separados, con sus propias herramientas de control de acceso. Unity Catalog los une: es el mismo principio del contrato de datos, aplicado también a lo que se construye con ese dato.
Tema 3 de 4

Integración con Datasphere

El canal zero-copy

Ya vimos que una API es una toma de agua fija entre el origen y quien consume. Delta Sharing es exactamente eso, pero entre la planta (Datasphere) y la represa (Databricks): en vez de trasvasar el agua a un depósito propio, la represa abre una toma directa sobre la misma agua de la planta — sin duplicarla.

Sin zero-copy

Copiar el agua a otro embalse

Un pipeline de extracción replica los datos en Databricks.

+ tocá para ver más
El agua duplicada envejece: cada cambio en el origen exige otra vuelta de extracción, y mientras tanto ambos embalses pueden mostrar cosas distintas.
↔
Con Delta Sharing

Se abre una toma directa

La represa toma agua directo de la planta — no un trasvase a un depósito propio.

+ tocá para ver más
SAP Business Data Cloud Connect habilita esto en ambas direcciones: los datos permanecen en su lugar de origen, sin duplicarse en un segundo depósito (arquitectura zero-copy, vía OpenSharing).
Cuando se monta un share de SAP Business Data Cloud en Unity Catalog, no solo llega el dato: también viajan los metadatos semánticos — comentarios de tablas y columnas, claves primarias, etiquetas de gobierno. El contrato de datos no se pierde al cruzar de un embalse al otro.

Tema 4 de 4

Machine Learning e Inteligencia Artificial

El agua no solo se guarda — se usa para generar algo nuevo

Una represa no es solo un depósito más grande: es un depósito pensado para generar energía. Acá la reserva de agua gobernada se convierte en la materia prima para entrenar, versionar y servir modelos de Machine Learning e IA.

1 · Feature Store

La turbina se alimenta

Variables reutilizables, calculadas una vez, gobernadas por Unity Catalog.

+ tocá para ver más
Evita que cada equipo recalcule las mismas variables (edad del cliente, ticket promedio) de formas distintas — el mismo principio del contrato, aplicado a los insumos de un modelo.
→
2 · MLflow

Se registra el proceso

Experimentos, versiones y métricas de cada modelo entrenado.

+ tocá para ver más
Nada se pierde: se puede reproducir exactamente qué datos y qué parámetros generaron cada versión del modelo.
→
3 · Model Serving

La energía sale a la red

El modelo entrenado, expuesto para predecir en tiempo real o por lotes.

+ tocá para ver más
