Tema 2 de 4

Modelado analítico

Un modelo no desaparece al entrar a SAC

Un Modelo Analítico puede seguir siendo el mismo Data Product que ya conocés — o convertirse en una copia local, con vida propia. La diferencia importa.

Live

El mismo modelo, gobernado

SAC consulta Datasphere en tiempo real, sin copiar nada.

+ tocá para ver más
Un cambio en Datasphere se refleja al instante en SAC. Respeta el Data Access Control automáticamente: es el mismo Data Product, visto desde otra ventana.
↔
Import (Acquired)

Una copia local, en SAC

Los datos se replican dentro de SAC — y pueden enriquecerse con cálculos propios.

+ tocá para ver más
Si el modelo de origen en Datasphere cambia, la copia no se entera sola — hay que reprogramar la importación. Y todo lo que se agregue acá (fórmulas, jerarquías) vive solo en SAC, fuera del contrato gobernado.
Todo modelo de Planning es, por naturaleza, un modelo Import: necesita sus datos replicados para poder soportar escritura y versionado (salvo integración con SAP BPC Embedded). No es una limitación — es la contracara lógica de lo que vimos en el Tema 1.
Tema 3 de 4

Stories y Visualización

El mismo dato, distintas lecturas

Una story en SAC no es algo genérico, sino una decisión de diseño: ¿controlás cada píxel, o dejás que se adapte solo?

Canvas

Vos controlás cada píxel

Posición y tamaño fijos, como una página impresa.

+ tocá para ver más
Ideal cuando el story se consume siempre en la misma pantalla — una TV en una sala de control, un tablero fijo. No se adapta a otros tamaños de pantalla.
↔
Responsive

Se adapta a la pantalla

Estructura fluida en filas y columnas, como una página web.

+ tocá para ver más
Ideal cuando el story se abre desde distintos dispositivos — laptop, tablet, celular. A cambio, se cede el control exacto de la posición.
Dentro de cualquiera de los dos modos, una story se arma con widgets (gráficos, tablas, filtros), se conecta entre sí con linked analysis — tocás un gráfico y el resto reacciona — y se ajusta con variables y prompts para que cada usuario vea su propio recorte. Cuando la configuración estándar no alcanza, Data Analyzer y el scripting en JavaScript abren la puerta a lógica a medida.
Tema 4 de 4

Planning

Cuando el dato deja de ser solo consulta

Hasta acá, SAC solo leía. Planning es cuando empieza a escribir — y eso cambia todo lo que hay que gobernar.

1 · Versionar

Actual, Plan, Forecast

No son etiquetas: cada una define qué tan editable es el dato.

+ tocá para ver más
Una versión "Actual" normalmente es de solo lectura; una versión "Plan" o "Forecast" habilita escritura para quien tenga permiso.
→
2 · Accionar

Data Actions y Allocations

Lógica de negocio ejecutada sobre datos de planificación.

+ tocá para ver más
Una Data Action puede repartir un total entre dimensiones (Allocation) o encadenar varias reglas (multi-action) — sin que el usuario final tenga que calcularlo a mano.
→
3 · Cerrar

Data Locking

Cuándo un período deja de poder tocarse.

+ tocá para ver más
Es el control real: si un período cerrado se puede seguir editando, la categoría de datos es decorativa, no una garantía.
Así como el contrato de datos protegía una misma mirada del dato para producir múltiples data products sin corromperla, el Data Locking protege una misma versión de planificación para que distintos equipos la alimenten sin pisarse — es el mismo principio de gobierno, aplicado a la escritura en vez de a la lectura.
